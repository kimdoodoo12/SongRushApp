# 089: draw set 3,000 (C-018)

From S-007, design `docs/design/088-songs-3000-covers.md`, decisions D-102 and D-107.

## Goal

The catalog's draw set holds the top 3,000 OP/ED themes by popularity instead of 1,500, rebuilt from the cached sources, and the build reports how many draw-set themes belong to the top 100 and top 300 anime.

## Acceptance criteria

1. `catalog.DRAW_SET_SIZE == 3000` (`data/songrush_data/catalog.py`).
2. Growing the draw size keeps the order: on a fixture, the first K entries of a build with draw size M > K equal the build with draw size K (prefix-stable).
3. `build_catalog` returns `report["animeRankThemes"]`, a dict with keys `"100"` and `"300"`: the number of draw-set themes whose anime is among the first 100 (or 300) distinct anime in draw-set order. When the draw set has fewer anime than the cut, the value counts all draw-set themes. `build.run` logs one line `build animeRankThemes 100=<n> 300=<m>`.
4. `data/catalog.json` is rebuilt with `python -m songrush_data.build` from the existing cache. The only live request allowed is the one AnimeThemes last-page freshness POST the build always makes (`animethemes.py:278-279`, pinned by `test_build.py:344-349`). The verifier checks the build log for all of these, and if any fails the rebuild is not committed and the cycle goes to Needs decision:
   1. pages 1-51 all logged `(cached)`, and `crawl pages=51 anime=5021 total=5021`;
   2. no `gained`, `restarting`, `total grew`, `anilist batch`, `wikidata batch`, `aod downloaded` or `anidb downloaded` line;
   3. `anilist media=5004 missing=0 cached=5004` and `wikidata ids=5004 ... cached=5004`;
   4. `build counts` shows anime 5021, themes 14591, groups 3321, drawSet 3000;
   5. `git diff data/catalog.json` changes only `drawSet` lines, and the first 1,500 `drawSet` entries equal the committed ones.
5. `.venv\Scripts\python.exe -m pytest` from `data/` exits 0, and `.\gradlew.bat test` from `backend/` exits 0 with the new `catalog.json` (CatalogBeanTest and NormalizeTest read it).
