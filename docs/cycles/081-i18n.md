# 081 i18n (D-095)

## Decision (owner, 2026-11-07)
The site targets players worldwide.
- **Languages:** the UI text comes in Korean, English and Japanese.
- **Choosing a language:** it is detected from the browser on the first visit (unknown languages fall back to English), and a language switcher changes it. The choice is remembered. Each player sees their own language, even in a shared room.
- **Reveal card titles:** the card shows the anime title in all four answer languages: Korean, English, Japanese and romaji.
- **Library:** react-i18next, the industry standard (owner's pick). D-023's "UI language: Korean" is replaced.

## Behaviour
1. **Libraries.** Add `i18next`, `react-i18next` and `i18next-browser-languagedetector`, at exact pinned versions at least two weeks old. Resources live in `frontend/src/i18n/{ko,en,ja}.json`, one key per UI string. They are bundled, not fetched over the network.
2. **Detection order.**
   1. The stored choice in `localStorage['songrush.lang']`, one of `ko`, `en` or `ja`.
   2. Then `navigator.languages`. Any `ko-*` maps to `ko`, `ja-*` to `ja`, and everything else to `en`.
   3. `fallbackLng` is `en`.
   - **Test mode** (`import.meta.env.MODE === 'test'`): the initial language is fixed to `ko`, so every existing locked test, written against Korean text, keeps passing unchanged. A test may switch the language explicitly.
3. **Switcher.**
   - A small control in the page footer: a `role="group"` with `aria-label="Language"` and three `<button aria-pressed>` buttons labelled `한국어`, `English` and `日本語`, each written in its own language.
   - Clicking one changes the language at once, stores the choice and sets `<html lang>`.
   - Its boxes must not depend on the room theme (the cycle 076 rules hold).
4. **Every visible UI string goes through `t()`.** This covers:
   - the start screen, lobby, game, chat and errors;
   - the reconnect banner, the sound prompt, theme names, seat labels (`빈 자리`, `(방장)`, `(나)`, `정답!`);
   - the stage (round `n / N` label, seconds, hint, skip `n/m`), the reveal labels, the system chat line `✔ <name> 정답!`, the scoreboard and ranking;
   - the credit line and the document title.
   - The server's error codes keep their codes. Their texts come from the dictionary.
   - **Theme names:** play 놀이터 / Playground / あそびば, neon 무대 / Stage / ステージ, sakura 벚꽃 / Sakura / さくら, chalk 칠판 / Chalkboard / こくばん, star 별밤 / Starry Night / ほしぞら, arcade 오락실 / Arcade / ゲーセン.
   - Korean strings must stay byte-identical to today's, so that the locked tests still match.
5. **Reveal card.**
   - The title area shows up to four lines, labelled KO, EN, JA and Romaji, using the first entry of `titles.ko`, `titles.en`, `titles.ja` and `titles.romaji` from the reveal frame. Missing languages are left out.
   - The card's big title is the line in the current UI language when it exists, otherwise the frame's `reveal` text. The other lines are smaller.
   - The existing reveal texts that the locked tests read (the `reveal` title, the theme slug, song, artists and winner) stay rendered once each in the Korean UI.
   - Theme box equality still holds (the cycle 077 check).
6. **Layout.** English and Japanese strings can be longer. Fixed-width labels must still fit, or truncate with the full text kept in the DOM. The lead's browser check covers this.

## Acceptance
**Tests** (`frontend/src/App.i18n.test.jsx`, new):
1. **Default.** In test mode the start screen is Korean. Clicking `English` shows English text on the start screen (the button `Create room`, the nickname label `Nickname`) and stores `en` in `localStorage['songrush.lang']`. Clicking `日本語` shows the Japanese equivalents.
2. **Stored choice.** With `songrush.lang = 'ja'` stored before mount, the app starts in Japanese.
3. **English game.** In English, a full room game renders English stage texts (the hint, the skip label) and the system chat line `✔ <name>` plus the English "got it" wording. Exact strings come from `en.json` (imported in the test).
4. **Reveal titles.** The reveal card shows the KO, EN, JA and Romaji lines from a reveal frame that has all four, and omits a missing language.
5. **Language and theme names.** Switching language does not change the room theme. The picker's buttons show the theme names in the selected language.
6. **Dictionary keys.** A node unit test (`frontend/src/i18n/keys.test.js`) checks that `ko.json`, `en.json` and `ja.json` have exactly the same key set and no empty values.

**Commands.** All earlier tests pass unchanged. `npm test`, `npm run lint` and `npm run build` exit 0.

**Lead's browser check.** In each of the three languages: the start screen, lobby and game render with no clipping (`scrollWidth <= clientWidth + 1` on fixed-width labels), the theme box equality is still 0 differences, and the switcher works.

## Out of scope
- Translating chat or server data.
- Right-to-left languages.
