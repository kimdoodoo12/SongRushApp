# SongRush 배포 안내서 (주인용)

이 안내서는 개발자가 아닌 분이 혼자서 따라 할 수 있게 썼습니다.
AWS 계정을 만드는 것부터, 친구들이 들어올 수 있는 인터넷 주소가 생기는 것까지 순서대로 설명합니다.

읽는 방법:

- 번호가 붙은 단계를 위에서부터 차례로 합니다.
- 회색 상자 안의 글은 그대로 복사해서 붙여 넣는 명령입니다.
- `<address>`, `<key.pem>`처럼 꺾쇠괄호로 묶인 부분은 **꺾쇠괄호까지 지우고** 자기 값으로 바꿉니다. 예를 들어 `<key.pem>`은 `songrush-key.pem`이 됩니다.
- 각 단계 끝에 "이렇게 보이면 성공"과 "안 되면"이 있습니다.
- AWS 화면의 버튼 이름은 가끔 바뀝니다. 이 안내서와 이름이 조금 달라도 뜻이 같은 버튼을 누르면 됩니다.

## 1. 무엇을 얻게 되나요

이 안내서를 끝내면 AWS(아마존의 클라우드 서비스) 안에 SongRush 게임 서버가 한 대 돌아가고, `https://203-0-113-10.sslip.io` 같은 주소가 생깁니다.
그 주소를 친구들에게 보내면 브라우저로 바로 방을 만들고 같이 퀴즈를 할 수 있습니다.

한눈에 보기:

- **걸리는 시간:** 처음 한 번은 1-2시간쯤입니다. 여기에 음원 약 5 GB를 올리는 시간이 더해집니다(집 인터넷 속도에 따라 20분에서 1시간 넘게).
- **비용:** 새 계정은 크레딧(AWS가 주는 사용료 쿠폰) 100달러를 받고, 정해진 활동을 하면 최대 100달러를 더 받습니다. 크레딧이 남아 있는 동안(대략 6-7개월)은 내는 돈이 없습니다.
- **크레딧이 떨어진 뒤:** 한 달에 약 14.6달러(2만 원쯤)입니다. 내역은 서버 약 9.5달러, 저장 공간 약 1.5달러, 공인 IP 약 3.7달러입니다.

## 2. 시작하기 전에: 아직 정하지 않은 것들

아래 세 가지는 아직 주인이 정하지 않았습니다. 이 안내서는 각각 **추천안**을 따라 씁니다. 다른 쪽을 고르면 무엇이 달라지는지도 적었습니다.

- **D-068 (AWS 가입 방식).** 추천: **Paid 플랜(유료 플랜)으로 가입하고, AWS Budgets 요금 알림을 겁니다.**
  - 유료 플랜도 무료 플랜과 같은 크레딧을 받습니다. 대신 크레딧이 떨어져도 계정이 닫히지 않습니다. 요금 알림이 있으니 돈이 나가기 시작하면 메일로 알 수 있습니다.
  - 무료 플랜(Free 플랜)을 고르면: 6개월이 지나거나 크레딧을 다 쓰면 계정이 저절로 닫히고, 90일 뒤에 서버와 음원이 지워집니다. 3단계의 가입 화면에서 무료 플랜을 고르는 것만 다르고 나머지 단계는 같습니다. 10단계 끝의 "무료 플랜을 골랐다면"을 꼭 읽으세요.
- **D-066 (인터넷 주소).** 추천: **`<ip-with-dashes>.sslip.io` 모양의 무료 자동 주소.**
  - 가입도 돈도 필요 없습니다. 대신 서버를 껐다 켜면 IP가 바뀌어 주소도 바뀝니다(10단계).
  - 도메인을 사면(연 1만 5천 원쯤): Elastic IP(바뀌지 않는 고정 IP, 10단계)를 붙이고, 도메인 회사 화면에서 그 IP를 가리키게 설정합니다. 이 안내서의 `<address>` 자리에 산 도메인을 넣으면 되고, 주소가 바뀌지 않습니다.
  - DuckDNS(무료, 가입 필요)를 고르면: DuckDNS에서 이름을 만들고 서버 IP를 넣습니다. `<address>` 자리에 그 이름을 넣습니다. IP가 바뀌면 DuckDNS에서 IP를 고쳐야 합니다.
- **D-067 (다음 곡 미리 듣기 막기).** 추천: **지금은 아무것도 하지 않습니다.** 친구끼리 하는 동안은 이 안내서에 할 일이 없습니다. 암호화를 넣기로 하면 개발 작업이 먼저 끝나야 하고, 그 뒤 9단계(나중에 업데이트하기)대로 다시 올리면 됩니다.

## 3. AWS 콘솔에서 할 일

**AWS 콘솔** = 브라우저로 들어가는 AWS 관리 화면입니다.

### 3-1. 계정 만들기

1. 브라우저에서 AWS 홈페이지에 들어가 계정 만들기를 누릅니다.
2. 이메일, 비밀번호, 연락처, 결제용 카드를 차례로 넣습니다. 카드 확인을 위해 아주 적은 금액이 잠깐 결제되었다가 취소될 수 있습니다.
3. 플랜을 고르는 화면이 나오면 **Paid 플랜(유료 플랜)**을 고릅니다(D-068).
4. 가입이 끝나면 콘솔에 로그인합니다.

이렇게 보이면 성공: 콘솔 첫 화면이 보이고, 오른쪽 위에 계정 이름이 보입니다.
안 되면: 카드 확인이나 전화 인증에서 막히는 경우가 많습니다. 화면 안내대로 다시 시도하고, 그래도 안 되면 AWS 고객지원에 문의합니다.

### 3-2. 요금 알림 걸기 (AWS Budgets)

**AWS Budgets** = 돈이 정해진 금액보다 많이 나가면 메일로 알려 주는 기능입니다.
이것을 설정하는 일은 크레딧을 더 받는 활동 중 하나입니다. 콘솔 첫 화면이나 결제 화면에 크레딧 활동 목록이 보이면, 그 목록에서 시작하면 인정이 더 확실합니다.

1. 콘솔 위쪽 검색창에 Budgets를 넣고 들어갑니다.
2. 예산 만들기 버튼을 누릅니다.
3. 비용 예산(cost budget)을 고릅니다.
4. 금액은 **1달러**, 알림 기준은 **실제 비용(actual cost)**으로 정합니다.
5. 알림을 받을 이메일 주소를 넣고 저장합니다.

알아 둘 점: 크레딧으로 처리된 요금은 이 알림의 계산에 들어가지 않을 수 있습니다. 그래서 이 알림은 "크레딧이 떨어지고 실제 돈이 나가기 시작했다"는 신호로 생각하면 됩니다.

이렇게 보이면 성공: Budgets 목록에 방금 만든 예산이 한 줄 보입니다.
안 되면: 결제 화면에 들어갈 권한이 없다는 말이 나오면, 처음 가입한 계정(루트 계정)으로 로그인했는지 확인합니다.

### 3-3. 지역 고르기

**리전(지역)** = AWS 서버가 있는 도시입니다. 친구들과 가까운 곳이 빠릅니다.

1. 콘솔 오른쪽 위의 지역 이름을 누릅니다.
2. **아시아 태평양(서울), `ap-northeast-2`**를 고릅니다.

이렇게 보이면 성공: 오른쪽 위에 서울이 보입니다.
안 되면: 다음 단계에서 서버를 만들기 전에 반드시 서울로 바꿔야 합니다. 다른 지역에 만든 서버는 그 지역을 골라야만 보입니다.

### 3-4. 서버(인스턴스) 만들기

**인스턴스** = AWS 안의 컴퓨터 한 대입니다. **EC2** = 그 컴퓨터를 빌려 주는 AWS 서비스 이름입니다.
인스턴스를 만드는 일은 크레딧을 더 받는 두 번째 활동입니다.

1. 위쪽 검색창에 EC2를 넣고 들어갑니다.
2. 인스턴스 시작 버튼을 누릅니다.
3. **이름:** `songrush`처럼 알아보기 쉬운 이름을 넣습니다.
4. **운영체제(OS 이미지):** Ubuntu를 고르고, 목록에서 **Ubuntu Server 24.04 LTS**를 고릅니다. 64비트(x86)를 고릅니다.
5. **인스턴스 유형:** **`t3.micro`**를 고릅니다. 메모리 1 GiB짜리 작은 컴퓨터입니다.
6. **키 페어:** 새 키 페어 만들기를 누릅니다.
   - **키 페어** = 서버에 들어갈 때 쓰는 열쇠 파일입니다. 비밀번호 대신 씁니다.
   - 이름은 `songrush-key`처럼 정하고, 형식은 **`.pem`**을 고릅니다.
   - 만들기를 누르면 `songrush-key.pem` 파일이 내려받기 폴더에 저장됩니다. **이 파일은 다시 받을 수 없습니다.** 잃어버리지 말고, 다른 사람에게 보내지 마세요.
7. **네트워크 설정(보안 그룹):** 보안 그룹 생성을 고릅니다.
   - **보안 그룹** = 서버의 방화벽입니다. 어떤 문(포트)을 누구에게 열지 정합니다.
   - 아래 세 가지를 허용합니다.
   - SSH 포트 22: 출처를 "내 IP"(My IP)로만 둡니다. 서버 관리용 문이라 내 컴퓨터에서만 열어 둡니다.
   - HTTP 포트 80: 어디서나(인터넷, `0.0.0.0/0`) 허용합니다.
   - HTTPS 포트 443: 어디서나(인터넷, `0.0.0.0/0`) 허용합니다.
8. **스토리지(저장 공간):** 크기를 **16 GiB**, 종류를 **gp3**로 바꿉니다. 음원 약 5 GB와 프로그램이 들어갑니다.
9. 인스턴스 시작 버튼을 누릅니다.

이렇게 보이면 성공: 인스턴스 목록에 `songrush`가 보이고, 상태가 몇 분 안에 "실행 중"이 됩니다.
안 되면: `t3.micro`를 고를 수 없다는 말이 나오면 지역이 서울인지 다시 확인합니다. 그래도 안 되면 화면의 오류 문장을 그대로 개발자에게 보냅니다.

### 3-5. IP 주소 적어 두기

**공인 IPv4 주소** = 인터넷에서 이 서버를 찾는 번호입니다. 점으로 나뉜 숫자 네 개입니다.

1. 인스턴스 목록에서 `songrush`를 누릅니다.
2. 아래 세부 정보에서 퍼블릭 IPv4 주소를 찾아 메모장에 적어 둡니다.

이렇게 보이면 성공: `203.0.113.10`처럼 숫자 네 개가 보입니다(이 안내서의 숫자는 예시입니다).
안 되면: 비어 있으면 인스턴스가 아직 켜지는 중입니다. 1-2분 뒤 새로 고칩니다.

## 4. 인터넷 주소 만들기

sslip.io는 IP 번호를 그대로 이름으로 바꿔 주는 무료 서비스입니다. 가입이 필요 없습니다.

만드는 법: IP가 `a.b.c.d`이면 주소는 `a-b-c-d.sslip.io`입니다. 점을 빼기표(-)로 바꾸고 끝에 `.sslip.io`를 붙입니다.

예시: IP가 `203.0.113.10`이면 주소는 `203-0-113-10.sslip.io`입니다.

이 주소가 이 안내서의 `<address>`입니다. 메모장에 IP 옆에 같이 적어 둡니다.

## 5. 내 컴퓨터에서 한 번만 할 일 (Git Bash)

**Git Bash** = 윈도우에서 명령을 입력하는 검은 창 프로그램입니다. 이 안내서의 모든 명령은 Git Bash에서 입력합니다.
윈도우 시작 메뉴에서 Git Bash를 찾아 엽니다. PowerShell이나 명령 프롬프트가 아니라 꼭 Git Bash를 씁니다. PowerShell에도 같은 이름의 ssh 프로그램이 있지만, 이 안내서는 Git Bash 안의 ssh를 기준으로 합니다.

붙여 넣기: Git Bash 창에서 마우스 오른쪽 버튼을 누르고 Paste를 고르거나, Shift+Insert를 누릅니다. 명령을 붙여 넣은 뒤 Enter를 누릅니다.

### 5-1. 열쇠 파일 옮기기

내려받기 폴더의 `.pem` 파일을 `~/.ssh/` 폴더로 옮깁니다. `~`는 내 사용자 폴더(예: C:\Users\내이름)를 뜻합니다.

```bash
mkdir -p ~/.ssh
mv ~/Downloads/<key.pem> ~/.ssh/
ls ~/.ssh
```

이렇게 보이면 성공: 마지막 명령의 결과에 열쇠 파일 이름이 보입니다.
안 되면: "No such file"이 나오면 파일 이름이 맞는지, 정말 내려받기 폴더에 있는지 확인합니다.

### 5-2. 프로그램 만들기(빌드)

**빌드** = 소스 코드를 서버에서 돌아가는 파일로 만드는 일입니다. 먼저 프로젝트 폴더로 갑니다.

```bash
cd ~/Downloads/SongRushApp
```

게임 서버를 빌드합니다. 몇 분 걸립니다.

```bash
cd backend && ./gradlew.bat build
cd ..
```

이렇게 보이면 성공: 끝에 BUILD SUCCESSFUL이 보입니다.

화면(웹페이지)을 빌드합니다.

```bash
cd frontend && npm ci && npm run build
cd ..
```

이렇게 보이면 성공: 끝에 built in 몇 초 같은 문장이 나오고 오류(error)가 없습니다.
안 되면: 빨간 오류 문장이 나오면 그 부분을 복사해 개발자에게 보냅니다. 두 빌드 모두 성공해야 다음으로 갑니다.

## 6. 서버에서 한 번만 할 일

여기부터 `<address>`는 4단계에서 만든 주소, `<key.pem>`은 열쇠 파일 이름입니다. Git Bash가 프로젝트 폴더(SongRushApp)에 있는지 먼저 확인합니다.

```bash
pwd
```

이렇게 보이면 성공: 나온 줄의 끝이 SongRushApp입니다.
안 되면: 아래 명령으로 프로젝트 폴더로 간 뒤 다시 확인합니다.

```bash
cd ~/Downloads/SongRushApp
```

### 6-1. 설치 도구 보내기

**scp** = 내 컴퓨터의 파일을 서버로 복사하는 프로그램입니다. 프로젝트 안의 deploy 폴더(설치 도구 모음)를 서버로 보냅니다.

```bash
scp -r -i ~/.ssh/<key.pem> deploy ubuntu@<address>:~
```

서버에 처음 연결하면 이런 질문이 나옵니다. `yes`를 입력하고 Enter를 누릅니다.

```text
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

이렇게 보이면 성공: setup.sh, upload.sh 같은 파일 이름이 100%와 함께 몇 줄 지나갑니다.
안 되면:

- "Connection timed out"이면 3-4단계의 보안 그룹(SSH 22, 내 IP)과 주소를 확인합니다.
- "Permission denied (publickey)"이면 열쇠 파일이나 사용자 이름이 틀린 것입니다. 5-1단계의 마지막 명령으로 `~/.ssh/` 안의 파일 이름을 다시 보고, 명령에 그 이름을 정확히 썼는지, 꺾쇠괄호를 지웠는지, 주소 앞이 ubuntu@인지 확인합니다.
- 열쇠 파일 오류는 8단계 끝의 "열쇠 파일 오류가 나면"을 봅니다.

### 6-2. 서버에 접속하기

**ssh** = 서버에 원격으로 들어가 명령을 입력하게 해 주는 프로그램입니다.

```bash
ssh -i ~/.ssh/<key.pem> ubuntu@<address>
```

이렇게 보이면 성공: 맨 아래 줄이 ubuntu@ip-로 시작합니다. 이제부터 입력하는 명령은 내 컴퓨터가 아니라 서버에서 실행됩니다.
안 되면: 위 6-1의 "안 되면"과 같습니다. 첫 연결 질문이 다시 나오면 `yes`를 입력합니다.

### 6-3. 서버 준비 프로그램 실행

setup.sh가 서버에 Java, 웹 서버(Caddy), 게임 서비스 설정을 깔고, 주소에 맞는 HTTPS 인증서를 준비합니다. **sudo** = 관리자 권한으로 실행한다는 뜻입니다.

```bash
cd deploy && sudo bash setup.sh <address>
```

몇 분 걸립니다. 글이 많이 지나가도 정상입니다. 끝나면 이런 줄이 보입니다.

```text
done. Next, from the PC: bash deploy/upload.sh ubuntu@203-0-113-10.sslip.io
```

이렇게 보이면 성공: 마지막 줄이 done.으로 시작합니다. 이 줄에 나온 upload.sh 명령에는 열쇠 파일이 빠져 있으니 그대로 쓰지 말고, 7단계의 명령을 씁니다.
안 되면:

- "lock"(잠금)이라는 말과 함께 멈추면, 서버가 처음 켜지면서 자체 업데이트를 하는 중입니다. 1분쯤 기다렸다가 같은 명령을 다시 실행합니다. 여러 번 다시 실행해도 안전합니다.
- 그 밖의 오류는 마지막 몇 줄을 복사해 개발자에게 보냅니다.

끝나면 서버에서 나옵니다.

```bash
exit
```

이렇게 보이면 성공: 맨 아래 줄이 다시 내 컴퓨터 이름으로 바뀝니다.

## 7. 올리고 시작하기

다시 내 컴퓨터의 Git Bash에서, 프로젝트 폴더(SongRushApp)에 있는 상태로 실행합니다. upload.sh가 빌드한 프로그램, 화면 파일, 곡 목록, 음원을 서버로 보내고 게임을 켭니다. 첫 줄은 프로젝트 폴더로 가는 명령입니다.

```bash
cd ~/Downloads/SongRushApp
bash deploy/upload.sh ubuntu@<address> ~/.ssh/<key.pem>
```

처음에는 음원 약 5 GB를 보내므로 오래 걸립니다. 중간에 인터넷이 끊기거나 창을 닫아도 괜찮습니다. 같은 명령을 다시 실행하면 이미 보낸 곡은 건너뛰고, 보내다 만 곡은 이어서 보냅니다.

이렇게 보이면 성공: 마지막 두 줄이 이렇게 나옵니다.

```text
healthy
done.
```

안 되면: done. 대신 서버 기록(로그) 수십 줄과 함께 이런 줄이 나옵니다.

```text
upload.sh: songrush is not healthy on ubuntu@203-0-113-10.sslip.io. To restore the last good jar (songrush.jar.good), run:
```

- 그 아래 줄에 "마지막으로 잘 돌던 버전으로 되돌리는 명령"이 나옵니다. 업데이트(9단계)할 때 실패했다면 그 명령을 그대로 붙여 넣어 실행하면 예전 버전으로 돌아갑니다.
- **처음 배포할 때는 이 되돌리기 명령이 통하지 않습니다.** 잘 돌던 버전(songrush.jar.good)이 아직 없기 때문입니다. 대신 위에 나온 로그 줄을 복사해 개발자에게 보냅니다.
- "is missing"이라는 말이 나오면 빌드나 음원 파일이 없다는 뜻입니다. 5-2단계를 다시 하거나, 음원 준비는 개발자에게 부탁합니다.

## 8. 잘 되는지 확인하기

smoke.py가 사이트를 네 가지로 검사합니다(서버 상태, 화면의 출처 문구, 방 링크, 실시간 연결). 내 컴퓨터의 Git Bash, 프로젝트 폴더에서 실행합니다. 첫 줄은 프로젝트 폴더로 가는 명령입니다.

```bash
cd ~/Downloads/SongRushApp
python deploy/smoke.py https://<address>
```

python을 찾을 수 없다는 말이 나오면, 프로젝트 안에 있는 Python으로 실행합니다.

```bash
data/.venv/Scripts/python.exe deploy/smoke.py https://<address>
```

이렇게 보이면 성공: OK로 시작하는 네 줄이 나옵니다.

```text
OK health
OK credit
OK room-link
OK websocket
```

그다음 브라우저에서 `https://<address>`에 들어가 방을 만들어 봅니다. 주소창에 자물쇠가 보이면 HTTPS가 잘 된 것입니다. 이 주소를 친구들에게 보내면 됩니다.

안 되면: FAIL로 시작하는 줄이 나옵니다. setup.sh를 막 실행했다면 인증서(HTTPS)를 뒤에서 받는 중일 수 있습니다. 1-2분 기다렸다가 smoke.py를 한 번 더 실행합니다. 그래도 FAIL이면 아래를 순서대로 확인합니다.

1. **주소가 지금 IP와 맞는지.** EC2 화면에서 퍼블릭 IPv4를 다시 보고, 4단계대로 만든 주소와 같은지 봅니다. 서버를 껐다 켰다면 IP가 바뀌었습니다(10단계).
2. **보안 그룹.** HTTP 80과 HTTPS 443이 어디서나(`0.0.0.0/0`) 열려 있는지 봅니다.
3. **인증서(HTTPS).** 서버에 접속(6-2단계)해서 웹 서버 기록을 봅니다. 오류 문장이 있으면 복사해 개발자에게 보냅니다.

   ```bash
   sudo journalctl -u caddy -n 50
   ```

4. **게임 서버.** 서버에서 게임 서버 기록을 봅니다. 마찬가지로 오류 문장을 복사해 보냅니다.

   ```bash
   sudo journalctl -u songrush -n 50
   ```

기록 화면이 길어서 멈춰 있으면 q를 눌러 빠져나옵니다.

### 열쇠 파일 오류가 나면

ssh나 scp가 이런 말을 하며 접속을 거부할 수 있습니다.

```text
WARNING: UNPROTECTED PRIVATE KEY FILE!
```

열쇠 파일을 다른 사용자도 읽을 수 있게 되어 있다는 뜻입니다. 윈도우 파일 권한에서 물려받은 권한을 없애고, 나만 읽을 수 있게 바꿉니다. Git Bash에서 실행합니다(빗금 두 개는 Git Bash에서 필요한 표기라 그대로 둡니다).

```bash
icacls ~/.ssh/<key.pem> //inheritance:r //grant:r "${USERNAME}:R"
```

이렇게 보이면 성공: "Successfully processed 1 files"가 나옵니다. 그다음 실패했던 명령을 다시 실행합니다.

## 10. 멈추기, 다시 켜기, 요금

### 멈춰 둘 때

안 쓰는 동안 EC2 화면에서 인스턴스를 **중지**(Stop)할 수 있습니다. 중지는 끄기만 하는 것이고, 데이터는 남습니다. 주의: 인스턴스 **종료**(Terminate)는 삭제라는 뜻이니 헷갈리지 마세요.

멈춰 둔 동안의 요금:

- **저장 공간(EBS, 서버의 디스크)**은 계속 요금이 나갑니다. 16 GiB면 한 달 약 1.5달러입니다.
- **자동으로 받은 공인 IP**는 중지하면 반납되고, 요금이 나가지 않습니다. 대신 다시 켜면 새 IP를 받습니다.
- **Elastic IP**(아래 설명)를 붙였다면 중지한 동안에도 요금이 나갑니다.

### 다시 켰을 때

EC2 화면에서 인스턴스를 **시작**(Start)하면, 게임 서버와 웹 서버는 저절로 켜집니다. 하지만 IP가 바뀌므로 주소도 바뀝니다. 아래를 차례로 합니다.

1. **새 주소 만들기.** 3-5단계처럼 새 퍼블릭 IPv4를 적고, 4단계처럼 새 주소를 만듭니다. 이것이 `<new-address>`입니다.
2. **내 IP 고치기.** 집 인터넷 IP도 바뀌었을 수 있습니다. 접속이 안 되면 보안 그룹에서 SSH 22 규칙의 출처를 다시 "내 IP"로 고칩니다.
3. **새 주소로 인증서 받기.** 아래 명령은 상자 하나씩 따로 붙여 넣습니다. 한꺼번에 붙여 넣지 마세요.

   먼저 내 컴퓨터의 Git Bash에서 6-2단계처럼 새 주소로 서버에 접속합니다. 첫 연결 질문이 다시 나오면 `yes`를 입력합니다.

   ```bash
   ssh -i ~/.ssh/<key.pem> ubuntu@<new-address>
   ```

   이제 서버 안입니다(맨 아래 줄이 ubuntu@ip-로 시작). 서버에 deploy 폴더가 남아 있으니, setup.sh를 새 주소로 다시 실행합니다.

   ```bash
   cd deploy && sudo bash setup.sh <new-address>
   ```

   마지막 줄이 done.으로 시작하면, 서버에서 나옵니다.

   ```bash
   exit
   ```

4. **새 주소 쓰기.** 이제부터 upload.sh와 smoke.py에도 새 주소를 씁니다. 친구들에게도 새 주소를 알려 줍니다. setup.sh를 막 실행했으니 인증서를 받는 데 1-2분 걸릴 수 있습니다. 1-2분 기다렸다가 프로젝트 폴더에서 확인합니다. FAIL이 나오면 1-2분 더 기다렸다가 한 번 더 실행합니다.

   ```bash
   cd ~/Downloads/SongRushApp
   python deploy/smoke.py https://<new-address>
   ```

### Elastic IP (바뀌지 않는 주소)

**Elastic IP** = 서버를 껐다 켜도 바뀌지 않는 고정 IP입니다. EC2 화면의 Elastic IP 메뉴에서 하나 받아 인스턴스에 연결하면 주소가 계속 같습니다.

- 서버가 켜져 있는 동안의 요금은 자동 IP와 같습니다(시간당 0.005달러, 한 달 약 3.7달러).
- 하지만 서버를 중지해 둔 동안에도 요금이 나갑니다.
- 붙이면 IP가 바뀌므로, 한 번은 위의 "다시 켰을 때"처럼 새 주소로 setup.sh를 다시 실행해야 합니다.

### 모두 지우기

더 이상 쓰지 않을 때, 요금이 남지 않게 지우는 순서입니다.

1. EC2 화면에서 `songrush` 인스턴스를 고르고 **종료**(Terminate)합니다. 서버와 그 디스크가 함께 지워집니다. 되돌릴 수 없습니다.
2. EC2 화면의 볼륨(Volumes) 목록이 비어 있는지 봅니다. 남은 볼륨이 있으면 삭제합니다.
3. Elastic IP를 받았다면 Elastic IP 메뉴에서 해제(Release)합니다.
4. 스냅샷(디스크 백업)을 만든 적이 있다면 스냅샷 목록에서 삭제합니다.
5. 키 페어와 보안 그룹은 요금이 없지만, 원하면 같은 EC2 화면에서 지웁니다.
6. AWS 계정 자체를 없애려면 계정 설정에서 계정 해지를 합니다.

다 지운 뒤 다음 달 청구서(결제 화면)에 요금이 없는지 한 번 확인합니다.
